## Notas / desalineaciones

- **A**: 1872 filas legacy → **1865** customers OSS. 7 filas legacy comparten
  dni/ruc con otras (ej. DNI 44445555 ×3). El contrato 0006 manda match por
  dni/ruc → se fusionan. Comportamiento correcto, distinto del conteo literal
  del criterio de aceptacion.
- **B**: `M3` NO existe en la BD legacy (verificado contra INFORMATION_SCHEMA:
  cero columnas M3/ADR). El endpoint expone `m3=0.0` + `peso_kg`,
  `peso_tara_kg`, `peso_total_kg` reales. Campo ADR_* fuera de alcance (Peru).
  Spec 0009 asumia columnas que no existen; el codigo real manda (ley de
  vigencia).
- **C**: 0015 inserta un egreso real en Movimiento/DetalleMovimiento via
  `sp_Movimiento_insertar` + `sp_DetalleMovimiento_Insertar` con
  `inventario=1, Estado=1, TipoAtencion=1, TipoMovimiento=3`, idempotente por
  clave guardada en `Observacion`. **Verificado contra BD real** (53→48→48→53
  con compensacion, ver tabla). Nota: el SP vivo exige parametro `@año`.
- Serializacion JSON: `JavaScriptSerializer` (System.Web.Extensions, incluido
  en .NET 3.5) en vez de Newtonsoft.Json (que vive en bin\Debug del ERP y es
  .NET 4.x); el contrato JSON es identico.
- VB9 (VS2008): sin continuacion implicita de linea; usar `_`. Sin
  initializers de Dictionary anidados. Archivos con BOM+CRLF.
- Bug legacy documentado: migracion 017 de logistics crea tabla con FK a
  `lg_mobile_warehouse_items` (tabla eliminada en 014); las migraciones de
  logistics no corren sobre schema actual (registry estampado a 055).
- OSS `stk_balance.updated_by` es NOT NULL sin default → el enlace debe
  asignarlo (actor = admin seed).
- SKUs legacy duplicados (ej. CIL101) → dedupe por sufijo `-<legacy_id>`.
