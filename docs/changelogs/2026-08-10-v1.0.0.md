# Changelog 2026-08-10 - Cierre de versión 1.0.0

## Estado

Se declara cerrada la **versión 1** del sistema desde el punto de vista funcional y operativo.

Este cierre significa:

- baseline estable para continuar como `v1.1+`;
- `logistics`, `stock`, `productos`, `crm` y `shell` ya forman un sistema usable end-to-end;
- la deuda técnica restante pasa a ser trabajo post-`v1`, no bloqueo de salida.

## Qué entra en el cierre de v1

### Kernel y runtime

- el backend dejó de contener wiring visible `kernel -> plugin` para reglas de negocio activas;
- el bootstrap estático de `logistics` salió de `apps/api/app/kernel/plugins/persistent.py` y ahora vive en hooks del propio plugin (`on_install`, `on_enable`);
- el listener `productos.product.created -> stock.ensure_balances_for_product` salió de `apps/api/app/kernel/events/tasks.py` y ahora vive dentro del plugin `stock`.

### Envases: lenguaje operativo final de v1

- el estado `EN_ALMACEN_VACIO` ahora se muestra como **`Vacío`** en la UI de `Envases`;
- el estado `LLENADO_OK` se muestra como **`Lleno`**;
- el KPI de `Lleno` en `Envases` ahora cuenta solo envases reales y excluye filas con `container_type = CRYOGENIC_TANK`.

### Lectura correcta del cierre

- `core` queda como infraestructura y runtime, no como owner de reglas de negocio plugin-específicas;
- `shell` queda como host estable del frontend modular;
- `logistics` queda estabilizado como primer flujo operativo serio del sistema;
- `stock` queda consolidado como contador/inventario transaccional integrable;
- `productos` queda como catálogo maestro y owner de recetas/ADR para operaciones asociadas.
