# SPEC 0023AD.2 — Asignación de envases por movimientos

## Estado

Evolución de 0023AD — 2026-07-11

> Esta spec reemplaza partes de `0023AD` (contratos envases) y `0023AO` (envases en posesión del cliente).
> Específicamente: elimina `lg_cylinder_contract_items` como fuente de `assigned` y lo reemplaza con cálculo desde movimientos reales SC/IC.
> 0023AD y 0023AO mantienen vigencia en todo lo no contradicho aquí.

## Problema

`lg_cylinder_contract_items` es una tabla puente contrato-cilindro que requería creación manual. En la práctica:

- el operador debía recordar crear un item por cada cilindro entregado
- el assigned dependía de disciplina manual, no de la operación real
- los movimientos SC/IC ya registran la misma información, pero no se usaban como fuente de verdad
- se duplicaba la realidad: movements decían una cosa, contract_items otra

**Síntoma en producción:** assigned mostraba 100 cilindros cuando realmente solo se habían entregado 50.

## Decisión arquitectónica

Eliminar `lg_cylinder_contract_items` como fuente de `assigned`.

A partir de ahora:

```
assigned = Σ(quantity_out WHERE movement_type = 'SC')
         - Σ(quantity_in  WHERE movement_type = 'IC')
         , clamped a 0
```

### Reglas de dominio

1. **Solo movimientos confirmados afectan assigned.** Movimientos en estado `PENDIENTE` o `CANCELADO` no tienen impacto en assigned. La fuente exclusiva son movimientos `COMPLETADO`. Esto aplica tanto a SC como a IC.

2. **Assigned es por cliente + producto, no por contrato.** Si un cliente tiene 2 contratos activos del mismo producto, assigned NO se divide ni se prorratea entre contratos. Es un saldo único por cliente+producto. La comparación con `contracted` (que sí suma todos los contratos activos del mismo producto) permite detectar excesos o faltantes.

3. **Identidad contable.** En todo momento debe cumplirse:

   ```
   assigned = at_customer + pipeline + lost
   ```

   Esta identidad es la herramienta de debug principal. Si no se cumple, hay un error en el pipeline de datos.

### Implicación de dominio

El sistema cambia de:

- ❌ **contract-driven**: el contrato define la realidad (pero requiere entrada manual)
- ✅ **movement-driven**: la realidad operativa (movimientos) define assigned; el contrato solo define expectativas (`quantity` = contractual, `assigned` = operativo)

Esto alinea el sistema con la operación real de GLP: los cilindros se alquilan por derecho a N envases, no por número de serie fijo.

## Diseño

### 1. SQL final

```sql
WITH movs AS (
  SELECT id, movement_type
  FROM lg_movements
  WHERE tenant_id = :tenant_id
    AND customer_id = :customer_id
    AND movement_type IN ('SC', 'IC')
    AND status = 'COMPLETADO'
),
agg AS (
  SELECT
    :customer_id AS customer_id,
    i.product_id,
    SUM(
      CASE
        WHEN m.movement_type = 'SC' THEN COALESCE(i.quantity_out, 0)
        WHEN m.movement_type = 'IC' THEN -COALESCE(i.quantity_in, 0)
        ELSE 0
      END
    ) AS raw_assigned
  FROM movs m
  JOIN lg_movement_items i ON i.movement_id = m.id
  WHERE i.product_id IS NOT NULL
  GROUP BY i.product_id
)
SELECT
  customer_id,
  product_id,
  GREATEST(raw_assigned, 0) AS assigned_quantity
FROM agg
WHERE raw_assigned > 0;
```

### 2. Mapping interno (Python, no migración)

```python
MOVEMENT_SIGN: dict[str, int] = {
    "SC": 1,   # entrega → suma
    "IC": -1,  # devolución → resta
}
```

Cuándo migrar a columna `direction` en `lg_movement_types`: cuando haya + tipos de movimiento con reglas de signo o reporting avanzado.

### 3. Protecciones

| Riesgo | Solución |
|--------|----------|
| NULL en quantity_in/out | `COALESCE(i.quantity_out, 0)` |
| Negativo por IC > SC | `GREATEST(raw_assigned, 0)` con raw visible para alertas |
| Cliente sin movimientos | Query retorna 0 filas → assigned = 0 |
| product_id NULL en items | `WHERE i.product_id IS NOT NULL` |
| Movimiento sin customer_id | `WHERE customer_id = :customer_id` (implícitamente no nulo) |
| Duplicados de movimiento | `lg_movements.id` es PK; no hay duplicación real |
| Movimiento no confirmado | `WHERE status = 'COMPLETADO'` |

## Impacto en tablas

### Eliminar

- `lg_cylinder_contract_items` (DROP)

### Crear

```sql
CREATE INDEX ix_mov_assigned
  ON lg_movements (tenant_id, customer_id, movement_type, status)
  INCLUDE (id)
  WHERE status = 'COMPLETADO' AND customer_id IS NOT NULL;
```

**Nota arquitectónica:** `status` aparece tanto en las columnas del índice como en la condición `WHERE` del partial index. En PostgreSQL el partial index es la optimización real — el `status` en columnas es redundante pero inofensivo. Se deja por claridad semántica en el orden de columnas.

## Transición: spike inicial de assigned = 0

### Problema

Al eliminar contract_items, todo cliente con cilindros en su poder mostrará `assigned = 0`, `at_customer > 0`, y `lost` se disparará.

### Solución: modo transición

En `customer_cylinder_summary.py`, mientras existan clientes sin assigned histórico:

```
if product.assigned == 0 AND product.at_customer > 0:
    # Verificar si hay movimientos históricos
    if not _has_any_movement(customer_id):
        product.lost = 0
        # alerta de transición
    else:
        # assigned=0 con movimientos existentes es inconsistencia real
        product.lost = at_customer  # pérdida real
```

**Importante:** El modo transición solo aplica cuando `assigned=0` Y **no hay movimientos históricos**. Si hay movimientos y assigned da 0, es una inconsistencia real (datos corruptos, IC sin SC previo, etc.) y debe reportarse como pérdida, no ocultarse.

Alerta específica en lugar de pérdida:

```
CustomerCylinderAlertRead(
    severity="INFO",
    category="transition",
    message="{n} cilindros de {product} en cliente sin assigned histórico. Se regulará con próximos movimientos."
)
```

### Condición de salida

El modo transición se elimina cuando:
- todos los clientes activos han tenido al menos un SC o IC desde la migración
- o se decide hacer backfill desde los contract_items existentes (Opción B, solo si producción real)

## Impacto en customer_cylinder_summary (0023AO)

### Candidate IDs — regla explícita

La fuente de cilindros a evaluar en el summary debe ser la **unión** de 3 fuentes. Ninguna es suficiente sola:

```python
def _customer_related_cylinder_ids(
    db: Session, *, customer_id: str, as_of: datetime | None
) -> set[str]:
    """
    Unión de 3 fuentes:
    - lg_cylinder_ownership          → custodia actual/pasada
    - lg_movement_items (SC/IC)      → cilindros en movimientos del cliente
    - lg_customer_cylinder_ledger    → posesión registrada por evento
    """
    ...
```

**Casos reales que cubre:**

| Caso | Fuente que lo captura |
|------|----------------------|
| Cilindro entregado en SC | movements |
| Cilindro aún en poder del cliente | ownership |
| Cilindro mal trackeado en ownership | ledger |
| Cilindro histórico sin movimiento reciente | ownership + state_log |

### Cambios en el summary

| Concepto | Antes | Ahora |
|----------|-------|-------|
| `assigned` | `SUM(contract_items.quantity)` entregado no devuelto | Saldo neto SC - IC desde movements |
| `contracted` | `SUM(contracts.quantity)` activos | Sin cambios |
| `at_customer` | Desde cylinders + ownership (sin cambios) | Sin cambios |
| `pipeline` | `assigned - at_customer` | `assigned - at_customer` (misma fórmula, distinto origen de assigned) |
| `lost` | Difícil de detectar | Inconsistencia matemática: `assigned - at_customer - pipeline` |
| `by_condition` | Incluía assigned por condición desde items | Solo contracted y at_customer por condición |
| `candidate_ids` | `tracked_ids ∪ ownership_ids` | `ownership_ids ∪ movement_ids ∪ ledger_ids` |
| Alertas `excess_assignment` | `assigned > contracted` | Sin cambios (ahora más precisa) |
| Alertas `shortage` | `assigned < contracted` | Sin cambios (ahora más precisa) |

### Modo transición en alerts

```python
if product.assigned == 0 and product.at_customer > 0:
    alerts.append(CustomerCylinderAlertRead(
        severity="INFO",
        category="transition",
        message=f"... datos históricos no migrados aún",
    ))
    # No disparar alertas de loss/shortage/excess para este producto
    continue  # saltar al siguiente producto
```
