# SPEC 0036.1 — Route Builder Map First

## Estado

Borrador — v2 (rediseño completo Map First)

## Frase guía

**El mapa es el constructor. El formulario solo confirma.**

## Objetivo

Rediseñar `RoutesPage` como un constructor visual Map First donde:

1. el mapa es la superficie central de creación y edición de rutas;
2. el nombre de la ruta se genera automáticamente desde el punto de partida y destino;
3. el flujo de creación tiene 3 fases guiadas: partida → destino → paradas intermedias;
4. el mismo constructor se abre desde `CreateJornadaDialog` cuando no hay rutas disponibles;
5. el contexto de ruta en jornada activa muestra un mapa minimal con los stops;
6. todo apunta a España por defecto (Madrid como centro).

## No objetivos

- no ruteo automático (distancia/tiempo entre puntos);
- no modificar `POST /routes` ni `POST /routes/{id}/stops`;
- no drag & drop sobre el mapa (solo reorden en sidebar);
- no afectar `RouteControlMapPanel` (telemetría en ejecución).

## `useRouteBuilder` — State Machine

```ts
type BuilderPhase = "idle" | "picking_start" | "picking_end" | "picking_stops";

type RouteStopDraft = {
  deliveryPointId: string;
  type: "start" | "end" | "stop";
};

type BuilderState = {
  phase: BuilderPhase;
  startPointId: string | null;
  endPointId: string | null;
  stops: RouteStopDraft[];        // solo type: "stop" (intermedias)
  routeDate: string;
  vehicleId: string;
  derivedName: string;            // "Partida → Destino"
};
```

### Transiciones

```
idle ──[+Nueva ruta]──→ picking_start
picking_start ──[click marker]──→ picking_end
picking_end ──[click marker]──→ picking_stops
picking_stops ──[click marker]──→ picking_stops (agrega parada)
picking_stops ──[Guardar]──→ idle
```

### Nombre derivado

Cuando `startPointId` y `endPointId` están definidos:
```ts
derivedName = `${startPoint.customer_name} → ${endPoint.customer_name}`
```
El campo es editable (input de texto).

## `RouteBuilderMap`

```ts
type Props = {
  deliveryPoints: LogisticsDeliveryPoint[];
  phase: BuilderPhase;
  startPointId: string | null;
  endPointId: string | null;
  stops: RouteStopDraft[];
  onClickMarker: (deliveryPointId: string) => void;
};
```

### Markers

| Fase | Markers disponibles | Acción al click |
|---|---|---|
| `picking_start` | Todos los DPs con coordenadas | Setea `startPointId` |
| `picking_end` | Todos menos el start | Setea `endPointId` |
| `picking_stops` | Todos menos start y end | Agrega parada intermedia |

### Íconos

| Tipo | Color | Etiqueta |
|---|---|---|
| Start | 🟢 | "Partida: {name}" |
| End | 🔴 | "Destino: {name}" |
| Stop intermedia | 🔵 | "Parada {n}: {name}" |
| Disponible | ⚪ | "{name}" |

### Polilínea

Conecta en orden: start → stops[0] → stops[1] → ... → end.

## Centro geográfico: España

Todos los mapas deben centrarse en Madrid por defecto cuando no hay coordenadas disponibles.

```ts
// Constante compartida
export const DEFAULT_MAP_CENTER = { lat: 40.4168, lng: -3.7038 };

// - RouteContextMap.tsx (fallback)
// - Solo se cambia en un lugar y se importa
```

## Reglas

1. El nombre de la ruta se deriva de partida y destino. Es editable pero se regenera si cambian start/end.
2. Partida y destino son obligatorios. Sin ambos no se puede guardar.
3. Las paradas intermedias son opcionales.
4. El mapa es la única forma de agregar paradas. No existe formulario alternativo.
5. Solo los delivery points con `gps_coordinates` no nulo aparecen en el mapa.
6. El constructor reutiliza `POST /routes` para crear la ruta y `POST /routes/{id}/stops` para las paradas.
7. Al crear ruta desde `CreateJornadaDialog`, al guardar se selecciona automáticamente.

---

## Riesgos

| Riesgo | Impacto | Mitigación |
|---|---|---|
| Delivery points sin coordenadas invisibles | Medio | Badge "X puntos sin coordenadas" en sidebar |
| UI compleja (sidebar + mapa + panel) | Medio | Layout responsivo, colapsar sidebar en móvil |
| Nombre derivado ambiguo si start/end son iguales | Bajo | Validación: start ≠ end |

---

## Criterios de aceptación

1. El operador crea una ruta eligiendo partida y destino con clicks en el mapa.
2. El nombre se genera automáticamente como "Partida → Destino".
3. Las paradas intermedias se agregan con clicks adicionales.
4. La ruta se guarda con partida, destino y paradas en orden correcto.
5. Desde `CreateJornadaDialog`, si no hay rutas, se puede abrir el constructor.
6. El contexto de ruta en la jornada muestra el mapa minimal con los stops.
7. Todos los mapas centran en Madrid por defecto.
8. `AddStopDialog` y el formulario viejo dejan de existir.
