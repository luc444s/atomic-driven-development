# SPEC 0036.2 — Direcciones de Cliente con GPS

## Estado

Borrador — v1

## Contexto

SPEC 0036.1 estableció el constructor Map First de rutas con clics libres en el mapa. Pero los stops no tienen contexto de cliente — solo coordenadas y un nombre genérico. El operador sabe que va a "Clínica San Pablo" pero el sistema solo ve `40.4168, -3.7038`.

El CRM ya tiene `latitude` y `longitude` en `crm_customer_addresses` pero no existe una UI para capturarlas. El módulo de direcciones de cliente (`AddressSection`) no tiene mapa.

Cerrar este gap beneficia dos módulos:
- **CRM**: las direcciones de clientes ganan coordenadas reales
- **Logistics**: el route builder puede mostrar direcciones de clientes como markers en el mapa

## Frase guía

**El cliente dice dónde está. La ruta sabe a quién va.**

## Objetivo

1. Agregar `LocationPicker` al formulario de direcciones del CRM para que cada dirección tenga coordenadas
2. En el route builder, mostrar las direcciones de clientes con GPS como markers diferenciados
3. Al seleccionar una dirección de cliente como parada, el stop guarda `customer_id`, `customer_name_snapshot` y la dirección
4. El nombre de la parada se deriva automáticamente: `"Cliente · Dirección"`

## No objetivos

- No reintroducir "Puntos de entrega" como UI separada
- No modificar `lg_delivery_points`
- No cambiar el flujo de creación de rutas (sigue siendo Map First)
- No forzar que toda parada tenga cliente (siguen siendo válidas las paradas genéricas con solo coordenadas)

## Arquitectura

El `LocationPicker` del core (`shared/ui/location-picker.tsx`) ya soporta:
- Click en mapa para poner marker
- Drag del marker
- Búsqueda por texto (Nominatim)
- Reverse geocoding (muestra dirección resuelta)
- Props: `value`, `onChange`, `height`

Al cambiar, actualiza `latitude`, `longitude`, `geocode_source = "MANUAL"`.

### Fase 2 — Route Builder: markers de clientes con GPS

**Archivos**: `RouteBuilderMap.tsx`, `useRouteBuilder.ts`

```
┌─ 🗺️ Mapa ───────────────────────────────────────────┐
│                                                       │
│   🟢 Clínica San Pablo                                │
│   📍 Av. Principal 123                                 │
│       │                                                │
│       🔵 Farmacia Y                                    │
│       │                                                │
│   📍 Jr. Secundario 456                                │
│       │                                                │
│   🔴 Hospital Central                                  │
│   📍 Calle Terciaria 789                               │
│                                                       │
└───────────────────────────────────────────────────────┘
```

El `RouteBuilderMap` recibe una nueva prop: `customerAddresses: CustomerAddress[]`.

Cada dirección con coordenadas se muestra como marker con ícono diferente (📍) y label `"Cliente · Dirección"`. Al hacer clic, se agrega como parada con `customerId`, `customerName`, `address`.

```ts
type CustomerAddress = {
  id: string;
  customerId: string;
  customerName: string;
  line1: string;
  latitude: number;
  longitude: number;
};
```

### Fase 3 — Backend: customer_id en RouteStop

**Modelo**: `LogisticsRouteStop`

```python
customer_id: Mapped[str | None] = mapped_column(
    ForeignKey("crm_customers.id"), nullable=True, index=True
)
customer_name_snapshot: Mapped[str | None] = mapped_column(String(120), nullable=True)
```

**Migración 041**: ALTER TABLE + FK.

**DTO**: `RouteStopCreateRequest` agrega `customer_id: str | None = None`, `customer_name_snapshot: str | None = None`.

**TypeScript**: `LogisticsRouteStop` agrega `customer_id: string | null`, `customer_name_snapshot: string | null`.

### Flujo completo

```
1. CRM: operador crea dirección de cliente + coordenadas vía LocationPicker
2. Route Builder: el mapa muestra 📍 markers de direcciones con GPS
3. Click en 📍 → parada con customer_id, customer_name, dirección, coordenadas
4. Nombre auto: "Clínica San Pablo · Av. Principal 123"
5. Guardar ruta → POST /routes/{id}/stops con customer_id + gps_coordinates
6. SessionRouteTab → RouteContextMap muestra nombre del cliente en cada stop
```

## Reglas

1. Las direcciones sin coordenadas no aparecen en el mapa del route builder
2. Una parada puede tener cliente (vía dirección CRM) o ser genérica (solo coordenadas)
3. El `customer_name_snapshot` se guarda al crear la parada para evitar joins innecesarios
4. `AddressSection` se actualiza en un solo lugar — todos los formularios de CRM lo heredan
5. El `LocationPicker` del core no se modifica — ya cubre el caso de uso

## Riesgos

| Riesgo | Impacto | Mitigación |
|---|---|---|
| Muchas direcciones saturan el mapa | Bajo | Solo mostrar si hay < 100; agrupar si > 100 |
| Dirección sin cliente crea stop huérfano | Bajo | El `customer_id` es nullable; el stop funciona igual |
| LocationPicker muy grande en formularios pequeños | Medio | `height={200}` compacto; colapsable en mobile |

## Criterios de aceptación

1. El formulario de dirección de cliente tiene un mapa para elegir coordenadas
2. Las coordenadas se guardan correctamente en `crm_customer_addresses`
3. El route builder muestra direcciones de clientes con GPS como markers
4. Al hacer clic en una dirección de cliente, la parada se crea con `customerId` y `customerName`
5. El nombre de la parada se genera como `"Cliente · Dirección"`
6. Al guardar la ruta, el stop persiste `customer_id` y `customer_name_snapshot`
7. Las paradas sin cliente siguen funcionando igual
