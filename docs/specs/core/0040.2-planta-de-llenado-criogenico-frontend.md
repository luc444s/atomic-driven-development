# SPEC 0040.2 - Planta de Llenado Criogenico - Frontend

## Contexto

La arquitectura base para criogenicos ya quedo fijada en `0040.1`:

- existe un `source_product_id` criogenico que se descuenta;
- existen seriales vacios predefinidos del tipo correcto (`result_product_id`);
- el llenado no crea un envase nuevo;
- el llenado solo transforma seriales vacios preexistentes a llenos.

Lo que falta cerrar ahora es la interfaz operativa de planta para ejecutar ese flujo de forma clara, repetible y auditable.

## Frase guia

**El operador entra desde Envases, elige un tanque criogenico, selecciona seriales vacios del tipo correcto y confirma un lote de llenado con preview claro del consumo en litros.**

## Objetivo

Definir la pantalla frontend de planta de llenado criogenico con estas reglas:

1. el punto de entrada vive dentro de `Envases`;
2. la pantalla muestra solo envases criogenicos fuente;
3. el operador puede llenar un solo cilindro o un lote serializado del mismo tipo;
4. el sistema muestra antes de confirmar el impacto en litros del criogenico;
5. el parcial permitido debe quedar visible antes de ejecutar.

## Punto de entrada

Dentro de `Envases`, en la fila superior de acciones, se agrega un boton nuevo:

```text
Llenado
```

Ubicacion esperada:

- visible en la esquina superior izquierda del bloque de acciones de `Envases`;
- no enterrado dentro de la ficha de un cilindro individual;
- pensado como entrada a la operacion de planta por lote.

ASCII art del entrypoint:

```text
+---------------------------------------------------------------+
| Envases                                                       |
|                                                               |
| [Llenado]                                      [Nuevo envase] |
+---------------------------------------------------------------+
```

## Pantalla principal

La accion `Llenado` abre una interfaz propia de planta de llenado criogenico.

### Vista inicial

La vista inicial lista exclusivamente los envases criogenicos fuente disponibles para llenado.

Formato esperado:

- cards;
- una card por envase/tanque criogenico;
- sin mezclar cilindros individuales en esta vista inicial.

ASCII art de la vista inicial:

```text
+--------------------------------------------------------------------------------+
| Planta de llenado criogenico                                                   |
|--------------------------------------------------------------------------------|
| Selecciona el envase criogenico fuente desde el que saldra el contenido.       |
|                                                                                |
| +----------------------------------+  +----------------------------------+     |
| | Envase criogenico de LOX         |  | Envase criogenico de LIN         |     |
| | TK-LOX-001                       |  | TK-LIN-003                       |     |
| | Disponible: 1000.000 L          |  | Disponible: 850.000 L           |     |
| | Capacidad: 5000.000 L           |  | Capacidad: 3000.000 L           |     |
| | [Iniciar llenado]               |  | [Iniciar llenado]               |     |
| +----------------------------------+  +----------------------------------+     |
+--------------------------------------------------------------------------------+
```

### Contenido minimo de cada card

Cada card debe mostrar:

1. nombre visible principal del envase criogenico
   - ejemplo: `Envase criogenico de Oxigeno Liquido`
2. codigo del envase/tanque en texto secundario y discreto
3. contenido actual disponible en litros
4. capacidad nominal si existe
5. estado operativo si existe
6. accion primaria para entrar al flujo de llenado

Ejemplo visual esperado:

```text
Envase criogenico de Oxigeno Liquido
TK-LOX-001
Disponible: 1000.000 L
Capacidad: 5000.000 L
[Iniciar llenado]
```

## Flujo de llenado

ASCII art del flujo completo:

```text
Envases
  |
  v
[Llenado]
  |
  v
Elegir criogenico fuente
  |
  v
Elegir tipo de cilindro
  |
  v
Seleccionar seriales vacios
  |
  v
Preview litros requeridos vs disponibles
  |
  v
Confirmar llenado
  |
  v
Resultado + fill_operation_id
```

## Paso 1 - Elegir criogenico fuente

El operador elige una card de criogenico fuente.

El sistema entra a una vista de trabajo donde ese criogenico queda fijado como origen activo.

Encabezado minimo:

- nombre del criogenico;
- codigo;
- litros disponibles;
- capacidad;
- producto fuente.

ASCII art del workspace una vez elegido el criogenico:

```text
+--------------------------------------------------------------------------------+
| LOX TK-LOX-001                                                                 |
| Producto fuente: Oxigeno Liquido - LOX                                         |
| Disponible: 1000.000 L                   Capacidad: 5000.000 L                 |
|--------------------------------------------------------------------------------|
| Tipo de cilindro resultado                                                     |
| [Seleccionar tipo.........................................................v]    |
|                                                                                |
| Seriales vacios del tipo elegido                                               |
| [Buscar serial............................................................]    |
| [Seleccionar lote] [Escanear]                                                  |
|                                                                                |
| Preview                                                                        |
| Solicitados: 0                                                                 |
| Litros por cilindro: -                                                         |
| Litros requeridos: -                                                           |
| Saldo proyectado: -                                                            |
|                                                                                |
|                                         [Cancelar] [Confirmar llenado]         |
+--------------------------------------------------------------------------------+
```

## Paso 2 - Elegir tipo de cilindro resultado

El operador debe elegir el tipo de cilindro resultado a llenar.

Restriccion:

- el lote solo puede mezclar seriales del mismo `result_product_id` por corrida visible de confirmacion.

Datos que la UI debe resolver y mostrar al elegir el tipo:

1. receta vigente:
   - `source_quantity_liters`
   - `result_m3_gas`
   - `result_net_weight_kg`
2. cantidad de seriales vacios disponibles del tipo correcto
3. maximo teorico llenable por stock fuente actual

## Paso 3 - Seleccionar seriales vacios

La pantalla debe permitir dos modos sobre el mismo tipo:

1. llenar un solo cilindro;
2. llenar un lote serializado.

La seleccion debe trabajar solo con seriales:

- vacios;
- del tipo correcto;
- disponibles para planta de llenado.

Entradas esperadas:

1. busqueda/scanner por serial individual;
2. selector de lote con lista de seriales elegibles;
3. accion de seleccionar `n` seriales del mismo tipo cuando exista cantidad suficiente.

No se permite en la misma corrida visible:

- mezclar tipos distintos;
- incluir seriales ya llenos;
- incluir seriales sin receta vigente asociada al tipo.

## Paso 4 - Preview antes de confirmar

Antes de ejecutar, la UI debe mostrar una tarjeta clara de resumen.

Contenido minimo:

1. criogenico fuente elegido;
2. tipo de cilindro resultado;
3. seriales seleccionados;
4. cantidad solicitada;
5. litros por cilindro segun receta;
6. litros totales requeridos;
7. litros disponibles actuales;
8. saldo proyectado del criogenico;
9. resultado esperado:
   - total
   - parcial

ASCII art del preview:

```text
+-----------------------------------------------------------+
| Preview de llenado                                        |
|-----------------------------------------------------------|
| Criogenico: TK-LOX-001                                    |
| Tipo: Oxigeno Industrial B10 / 200BAR                     |
| Seriales seleccionados: 100                               |
| Litros por cilindro: 2.516                                |
| Litros requeridos: 251.600                                |
| Litros disponibles: 1000.000                              |
| Saldo proyectado: 748.400                                 |
| Resultado esperado: TOTAL                                 |
+-----------------------------------------------------------+
```

## Paso 5 - Confirmacion

La accion final debe ser explicita:

```text
Confirmar llenado
```

La confirmacion debe dejar claro que:

- se descontaran litros del criogenico fuente;
- los seriales seleccionados pasaran a llenos;
- la corrida quedara auditada como una operacion comun.

## Politica de parcial visible

`0040.1` ya permite parcial explicito.

En frontend eso debe verse asi:

1. si el stock fuente no alcanza para todos los seriales seleccionados, la UI no debe mostrar exito total;
2. debe informar cuantas unidades pueden llenarse realmente;
3. debe permitir al operador:
   - ajustar la seleccion manualmente, o
   - confirmar el parcial de forma explicita.

Mensajes minimos esperados:

```text
Solicitados: 100 seriales
Stock fuente suficiente para: 60 seriales
La operacion sera parcial si continuas
```

ASCII art del caso parcial:

```text
+-----------------------------------------------------------+
| Preview de llenado                                        |
|-----------------------------------------------------------|
| Solicitados: 100 seriales                                 |
| Stock fuente suficiente para: 60 seriales                 |
| Litros requeridos para 100: 251.600                       |
| Litros disponibles: 151.000                               |
| Resultado esperado: PARCIAL                               |
|                                                           |
| [Ajustar seleccion]          [Confirmar parcial]          |
+-----------------------------------------------------------+
```

## Validaciones visibles

La UI debe bloquear confirmacion cuando ocurra cualquiera de estos casos:

1. no hay criogenico fuente elegido;
2. no hay tipo de cilindro resultado elegido;
3. el tipo no tiene receta vigente;
4. no hay seriales seleccionados;
5. los seriales seleccionados no son todos del mismo tipo;
6. algun serial no esta vacio;
7. algun serial no pertenece al tipo elegido.

## Resultado visible post-operacion

Al confirmar, la UI debe devolver como minimo:

1. litros descontados reales;
2. saldo final del criogenico;
3. cantidad llenada real;
4. seriales efectivamente llenados;
5. `fill_operation_id` o equivalente visible/auditado;
6. seriales no llenados si la corrida fue parcial.

## No objetivos

- no definir aun el layout exacto pixel-perfect;
- no rediseñar toda la pagina de `Envases`;
- no abrir todavia una pantalla de reconciliacion de planta;
- no resolver mermas/boil-off en esta iteracion;
- no mezclar este flujo con jornadas/rutas/vehiculos.

## Archivos esperados

| Archivo | Rol esperado |
|---|---|
| `plugins/logistics/frontend/LogisticsPage.tsx` | agrega el boton `Llenado` como entrada visible desde `Envases` |
| `plugins/logistics/frontend/.../cryogenic-filling/` | nueva seccion o workspace de planta de llenado |
| `plugins/logistics/frontend/api/...` | consumo del endpoint de criogenicos/fill batch cuando exista |
| `apps/web/src/shared/ui/` | solo reutilizar componentes core ya existentes |

## Criterios de aceptacion

1. Existe un boton visible `Llenado` dentro de `Envases`.
2. La vista inicial muestra solo cards de envases criogenicos fuente.
3. Cada card muestra nombre, codigo y litros disponibles.
4. El operador puede llenar un serial o un lote serializado del mismo tipo.
5. La UI muestra preview de litros requeridos vs litros disponibles antes de confirmar.
6. Si la corrida sera parcial, la UI lo declara explicitamente.
7. La confirmacion deja visible el `fill_operation_id` o correlacion equivalente.

## Encaje con 0040.1

`0040.1` fija la arquitectura minima del caso criogenico.

Esta spec solo baja esa arquitectura a flujo frontend operativo de planta:

```text
Envases -> Llenado -> elegir criogenico -> elegir tipo -> seleccionar seriales vacios -> preview -> confirmar
```
